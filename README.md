# 心迹画像 · Profile Weaver

**安全可控的 AstrBot 用户画像记忆插件 —— 只写当前说话人，句句留证据，附带一套好看的 Dashboard 管理面板。**

## 这个插件解决什么问题

大多数"记忆"插件的通病是**记错人**：群里 A 提到 B 的生日，模型就把生日写进了 A 的画像；或者把一句玩笑、一次角色扮演当成稳定事实存了下来。

心迹画像的做法是把写入变成一件**需要举证的显式操作**：

- LLM 不能"顺手"改画像，只能调用 `profileweaver_remember_field` / `profileweaver_forget_field` 工具；
- 每次写入必须附带 `evidence`（本轮消息中的原文片段），校验不通过直接拒绝；
- **身份护栏**：消息明显在谈论他人、缺少明确自述时拒绝写入；
- **字段黑名单**：敏感字段（默认 `健康状况`）永远只能由本人命令或管理员维护；
- **字段锁**：任何单个字段都能被逐一锁死，锁的拦截范围可配置（只拦 LLM / 也拦用户命令 / 谁都不许动）；
- 所有变更写入 `audit_log.jsonl`，谁改的、改前改后是什么、依据哪句话，全部可回溯，并可按字段回看单字段演变史。

在此之上，v3.0.0 补齐了运维侧（可视化面板、导入导出、每日自动备份与一键恢复），
v3.1.0 补齐了可观测与精细管控：字段锁、画像完整度评分、字段级变更历史、审计 CSV 导出、备份下载与删除。

### 面板打不开时

面板启动只依赖一个 `meta` 接口。拿不到时不会白屏，而是在总览位置渲染一张「面板无法启动」卡片，带上后端原始错误、常见原因清单和「重新尝试」按钮，**画像数据本身不受影响**。

常见原因按概率排序：

1. 插件配置里 `webui_enabled` 被关掉了 —— 关闭时接口根本不注册，报错会是「接口未注册」。
2. 插件刚更新还没重载 —— 重载插件后刷新页面。
3. AstrBot 版本过旧、不支持插件 Page。

所有 19 个接口都走统一兜底：请求体超限回 413、未预期异常回 500，**响应体永远是 JSON**，不会出现 Dashboard 的 HTML 错误页把前端解析打崩的情况。

## 画像字段

默认 26 个基础字段，全部可在配置里增删：

`昵称`、`性别`、`年龄`、`所在地`、`生日`、`爱吃`、`忌口`、`爱好`、`职业`、`重要节日`、`恐惧/弱点`、`作息规律`、`技能水平`、`健康状况`、`宠物`、`MBTI`、`星座`、`时区`、`常用语言`、`沟通偏好`、`禁忌话题`、`代词`、`喜欢的话题`、`口头禅`、`当前目标`、`备注`

> v3.1.0 新增 `代词`、`喜欢的话题`、`口头禅`、`当前目标` 四项。升级时它们会被自动追加到你现有的字段表末尾（`备注` 之前），
> 只补一次，不会覆盖你的排序或删减；不想要这个行为就关掉 `auto_adopt_new_builtin_fields`。

- `备注` 是多条列表字段，保留最近 N 条（`max_notes_count`），且在展示与导出中恒定排在最后。
- 基础字段不够用时，LLM 或用户可以创建**当前用户专属自定义字段**（如"最喜欢的国漫""常用编辑器"），受 `allow_llm_custom_fields` / `allow_user_custom_fields` / `custom_field_name_max_length` 约束。
- `时区`、`常用语言`、`沟通偏好`、`禁忌话题`、`代词`、`口头禅` 这几个字段对回复风格影响最直接，建议保留。

### 完整度评分

完整度 = 已填写的基础字段数 ÷ 基础字段总数 × 100%（自定义字段不计入分母，避免"越加字段越不完整"）。
面板的画像卡、抽屉头部、总览页，以及聊天里的 `画像完整度` / `画像统计` 都用同一套算法，<40% 显示为红、<75% 为黄、其余为主题色。

## 字段锁

任何字段都可以被单独锁定：`锁定画像 昵称`、管理员 `锁定用户画像 10001 昵称`，或在面板抽屉里点字段行上的锁按钮。
锁定状态存在画像记录的 `locked_fields` 里，锁与解锁都会写审计（`lock_field` / `unlock_field`）。

`field_lock_scope` 决定锁拦得有多狠：

| 取值 | 被拦住的来源 | 适合 |
| --- | --- | --- |
| `llm_only`（默认） | LLM 工具、自动提取 | 只想防模型乱改，本人和管理员照常维护 |
| `llm_and_user` | LLM 工具、自动提取、普通用户命令 | 昵称/称呼被反复改来改去时锁死 |
| `strict` | 所有来源，包括管理员命令与 WebUI | 合规场景，改之前必须显式解锁 |

> **解锁永远不受锁的限制**，否则 `strict` 会把自己锁死。
> 另外要注意：`清空画像` / `清空用户画像` / 删除整份画像 / 导入的 `replace` 模式**都不受字段锁约束** ——
> 字段锁保护的是"某个字段的值别被悄悄改掉"，不是"这份画像删不掉"。

## 字段改动历史

审计日志本来就是 append-only 的流水，v3.1.0 在它之上加了按字段的检索：

- 聊天里：`画像历史 昵称`、`画像历史 昵称 20`；管理员 `画像字段历史 10001 昵称`；
- 面板里：抽屉中每个字段行的「历史」按钮，就地展开该字段的 `旧值 → 新值`、操作者、来源与原文证据；
- 默认会一起翻已归档的 `audit_log.jsonl.<timestamp>`，所以轮转过也查得到。

## LLM 工具

| 工具 | 作用 |
| --- | --- |
| `profileweaver_view_profile` | 读取当前说话人的画像 |
| `profileweaver_remember_field` | 写入/更新一个字段，必须提供 `evidence` |
| `profileweaver_forget_field` | 删除一个字段，必须确认用户明确要求 |

写入被拒绝时工具会返回明确原因（黑名单 / 证据不匹配 / 身份护栏 / 重复 / 冲突），提示词要求模型如实告知用户"没有写入"。

此外还有一条**低开销自动提取**通路：仅当消息长度在区间内、看起来是明确自述、且主对话本轮没调用过画像工具时，才额外发起一次最多 2 步的后台工具循环（`proactive_extraction_*`）。像 `我最喜欢的国漫：凡人修仙传` 这种明确键值自述会走零额外 token 的本地兜底。

## 导入 / 导出

导出产物是一个 `profileweaver.bundle` v2 JSON：

```json
{
  "format": "profileweaver.bundle",
  "version": 2,
  "exported_at": "2026-08-29T12:00:00+08:00",
  "plugin_version": "3.1.0",
  "session_based": false,
  "masked": false,
  "profile_count": 42,
  "profiles": { "_10001": { "fields": {}, "field_meta": {}, "notes": [] } }
}
```

三种导入模式：

- **merge（合并）**：逐字段合并，同名字段以导入文件为准，其余保留 —— 最安全，默认；
- **overwrite（覆盖）**：同 key 的画像整份替换，其他 key 保留；
- **replace（替换）**：用文件内容整体替换现有数据。

任何导入之前都会自动创建 `pre-import-<mode>` 备份，并写入审计。

> **脱敏导出不可导入。** 开启 `export_mask_user_ids`（或在面板勾选脱敏）后，用户 ID、昵称以及审计记录里的操作者身份都会被不可逆打码，这类文件只能用于查看统计，导入会被明确拒绝。

另外两条导出通路（都不脱敏，谨慎分发）：

- **审计 CSV**：审计页右上角「导出 CSV」，13 列、带 UTF-8 BOM，Excel 直接双击就能看，沿用当前的筛选条件；
- **备份下载**：迁移页每份备份都能原样下载成 `.json`，用于离线归档或搬到另一台机器。

## 数据与文件

插件数据目录（AstrBot 分配）下：

```text
profiles.json                 # 主数据，原子写（临时文件 + 替换）
audit_log.jsonl               # 审计流水，超过 audit_log_max_mb 自动轮转
audit_log.jsonl.<timestamp>   # 轮转后的历史审计，最多留 audit_log_keep_rotated 份
backups/                      # 自动快照 + 手动 / 导入前 / 恢复前备份
profiles.json.corrupt-<ts>    # 主文件损坏时隔离的原文件（不会静默丢数据）
```

备份命名：自动快照是 `profiles-auto-YYYYmmdd.json`（每天首次写入时生成一份），
手动与自动前置备份是 `profiles-<标签>-YYYYmmdd-HHMMSS.json`。
清理时**天数与份数两个上限同时生效**（`backup_retention_days` / `backup_max_count`），任一超限就删最旧的。

历史版本的 `user_profiles.json` 会在首次启动时自动迁移。

## 安全须知

1. **Dashboard 鉴权就是画像的鉴权。** 面板 19 个接口挂在 AstrBot 的 `/api/plug/...` 下，**插件层没有任何额外鉴权**，只继承 Dashboard 的登录态。
   任何能登录 Dashboard 的人都能读写全部画像、导出全量审计明文（`audit-csv`）、下载完整画像快照（`backup-download`）、删除备份（`backup-delete`）。
   请务必给 Dashboard 设强密码，**不要把它暴露到公网**。
2. **数据是明文 JSON。** `profiles.json`、备份与审计日志都未加密，请按普通敏感数据对待（备份目录、快照、容器镜像都算）。
3. **只读模式**：把 `webui_allow_edit` 关掉后，改字段、删字段、删画像、合并、导入、锁定/解锁、创建/恢复/删除备份这 9 个写接口统一返回 403。
   注意只读模式**不会**关掉导出与下载 —— 它防的是误改，不是防泄露。
4. **导入是高风险操作。** `replace` 会整体替换数据；虽然导入前会自动备份，但请先确认文件来源可信 —— 导入文件里的字段值会被注入到后续的 LLM 提示词中。上传大小上限内置为 16 MB，超限会明确返回 413 而不是含糊的 400。
5. **脱敏包不可逆**，也不可导入，别把它当备份用；备份下载和审计 CSV 则**始终是明文**，不受 `export_mask_user_ids` 影响。
6. **字段锁不是删除保护。** 它只拦字段值的改写，`清空画像` 与 `replace` 导入照样生效。

## 安装

在 AstrBot Dashboard 的插件市场搜索安装，或手动克隆到插件目录：

```bash
git clone https://github.com/Whereis-Alice/astrbot_plugin_profile_weaver.git
```
